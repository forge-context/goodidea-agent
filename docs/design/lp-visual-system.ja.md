# GoodIdea LP Visual System と設計理由

[English](lp-visual-system.md) | [日本語](lp-visual-system.ja.md) | [中文](lp-visual-system.zh.md)

この記録は、現在の LP における Design 判断と理由を説明する。色に普遍的な心理効果があるとは決めず、「発散した Idea → 現実の根拠 → 収束した境界 → 行動」という Product Behavior に一貫した Interface Language を定める。

詳細なウォークスルーと実際のワークスペースは `shared/studio/` の Token、Studio スタイル、マップ描画を共用します。主 Demo の映像表現は `web/src/studio/paper/` に分離し、クラス名とカスタムプロパティは `gip-` 接頭辞で統一、共通の製品 UI は変更しません。

## 2026-09-09：ヒーローは 1 枚のイラストと、その上に置く 3 つの文

これまでヒーロー右半分は部品の寄せ集めだった。映像用の紙テクスチャ、キャラクターシートから抜いた 1 ポーズ、手書きの SVG ワイヤーフレーム、植物、そして回転した箱に対して配置した 5 つの手書き注記。成立していなかった。スプライトが終わる位置を紙で隠す必要があるため人物は上半身の半分しか出せず、定規で引いたようなワイヤーフレームが手描きの紙と並び、注記は破れた縁に近すぎて別々に浮いた層に見えた。

いまは支給された 1 枚のイラスト——`web/public/hero/goodidea-hero-illustration.webp`、1374×1145、104 KB——で、2 人の人物、主ドラフト、背後の紙、付箋、植物、ワイヤーフレーム、消した案、緑の線がすべて含まれている。CSS や SVG がそれらを描き直すことはなく、このファイルに無いレイヤーがあるふりもしない。

**画像は透過ではなく、その必要もない。** 地色は `#faf8f2`、ページの `--paper` は `#fbf8f2`。1440×900 のレンダリング結果で四辺を横切ってサンプリングすると、最大差は赤チャンネルの 1 段階だけ——隠すべき矩形が無いので、マスクもブレンドモードも使わない。ブレンドモードは手軽に見えて誤りだ。誰にも見えない縁を隠すために、肌と紙の色を動かしてしまう。

**文字は DOM。同じ絵が 3 言語を担うからだ。** 素材はあえて文字を持たない。3 つの文を重ね、位置は画像に対する百分率、角度はそれぞれの下にある紙の向きに合わせ、すべて素材から実測した。上部の長い緑線は (31.3%, 25.6%) から (69.1%, 31.2%) なので、その上の見出しは +7° 回る。楕円は中心 (70.8%, 53.8%)、半径 13.1% と 10.25% で、中の文はほとんど回らない。足元の短い線は -3°。3 つに同じ回転を当てれば、少なくとも 2 つは自分の線とずれて見える。

**楕円の中の改行は文案側にある。** 楕円は真ん中しか広くないので、幅で組んだ文字塊は必ず最初と最後の行が曲線からはみ出す。3 言語それぞれが自分の改行を持ち、塊の角から楕円までの正規化距離を確認した（0.77 / 0.61 / 0.66）。

**45 / 55、そして自分の半分を支えられる見出し。** イラストは広いほう、見出しは重いほう。大きな絵に小さな文字はキャプション付きのポスターに見える。見出しの上限は 42px から 53px へ。中国語と日本語の見出しは文案側で「一節一行」にした。`word-break: auto-phrase` は Chrome 限定で中国語を分節しないため、「可以」や「着手できる」が途中で切れていた。英語は一文のまま、列幅で自然に折り返す。

**動きは 16px、そして 1 つの物体として。** 画像と 3 つの文は同じ変換要素の中にあるので離れようがない。回転はさせない——地色を持つ矩形の絵を回すことこそ、縁が見える原因だからだ。スクロールはカスタムプロパティを 1 つ書くだけで、残りは CSS が担い、スクロール中にコンポーネントの状態は変わらない。画面外、スマートフォン、`prefers-reduced-motion` では完全に止まる。スマートフォンでは見出しだけを残す。他の 2 文はその幅だとページ自身の可読下限を下回る。

## 2026-09-08（続き）：ページの言語を一つに、Demo を前へ

ページは 3 つの視覚体系を同時に抱えていた——紫とコーラルのマーケティング表皮、その中のセージと紙の映像、そして暗い紫の締め。順序も、それらを説明するものへ辿り着く前に成果カードを 7 枚読ませていた。どちらも一つにまとめた。

- **配色は一つ、定義は `web/` の中。** 暖かい白の地、黒鉛色の文字、本文サイズでも主役になる深さのセージグリーン。淡いセージは選択・提案・控えめな強調だけに使い、調査のオーカー・UX の青灰・実装の茶は職能の identity のままで、区画ごとの色にはしない。外側の紫の光、紫の説明枠、暗い紫のグラデーションは削除。意味づけの変数は `web/src/styles.css` で上書きし、私有プロダクトも使う `shared/studio/` は触っていない。
- **マークは一つ。** サイトの G のパスを、ページのヘッダーとフッター、映像内のワークスペースのバー、GoodIdea 自身のカード、そして締めの画面で使う。映像内のイタリック小文字 `g` は廃止。形は一つ、色も一つ、大きさが三つ。
- **UI の書体は一つ。** 本文・ナビ・状態・決定カード・すべてのコントロールはシステムのサンセリフ。手書きは、作り手自身の言葉・実際の書き込み・インクだけに残す。
- **順序：位置づけ → Demo → 成果物 → 誰が決めるか → 短い締め。** 映像が論拠なので、ヒーローとの間には何も置かない。ヒーローには短い動きのあるパネルを置いた——署名つきの提案 3 件が集まり、GoodIdea がまとめ、決定はあなたのもので、その後ろでドラフトが埋まっていく。事例ではなく製品の形を示す。事例は下の Demo と成果物の節のもので、ヒーローに置くと題名と価格のせいで見積ツールのサイトに読めてしまう。パネルは一度だけ動いて止まる。旧いルートマップではないし、ループもしない。
- **成果物はドラフト 1 枚と 2 つのまとまり。** 最初の一文・方向・スケッチを載せた 1 枚、その横に初版でやること／やらないこと。完了条件・未検証の仮説・実装の作業は開閉の中。必要な境界が要約の裏に隠れることはない。
- **進め方と、あなたが握り続けるものを 1 つの節に。** 実際のふるまいを 3 手順、その下に 3 つの原則。製品として目指す形（地図の上で直す、試作の中で要望を言う）は目標として明記した。公開している映像にその操作はまだない。
- **境界の説明は、最後に一度だけ全文で。** プレイヤーの脇には短い「コンセプト映像・固定の例」、未検証の項目にはその場の印を残すが、段落を節ごとに繰り返さない。

### 決定カードと、それを押すポインタ

ボタンは問いを出しているカードから離れていた。用紙の下端にぶら下がり、説明との間には空白の帯があり、模擬ポインタはそれとは別に書かれた座標を狙っていた——矢印の先は押すはずのコントロールの数ピクセル上に着き、押すとコントロールはさらに下へ逃げた。

- コントロールは決定カードの中の最後の要素になり、通常のフローに乗る。順序は、あなたの決定 → 提案 → 説明 → 今回やらないこと → 出どころ → 採用ボタン。どの言語でも用紙の内側で余裕をもって終わる。
- ポインタは座標を持たない。タイムラインはどのコントロールへ向かい、どこまで進んだかだけを言い、ステージが実際に組まれた箱から両端を解決して、用紙自身の変換を通す。矢印の先（24 単位のスプライトの 4, 2）が唯一の hotspot で、スプライトはそこで配置され、押下はそこを原点に縮み、波紋はそこを中心にする。
- 文にかかるインク——最初の説明を消す取り消し線、発見に引く下線、未決の問いを囲む丸——は、その文が実際に占める箱から生成される。長い言語では文字とインクが一緒に動く。以前は 2 行のうち 1 行しか消しておらず、英語の下線は 3 分の 2 で止まっていた。
- 移動は、その名前がついた拍の 1 フレーム前に終わる。「到着」のフレームでポインタはすでにコントロールの上に落ち着いていて、まだ手を伸ばしている途中ではない。

### スマートフォンは一度に一つ読む

760 単位のステージを丸ごと縮めて「読める」ことにするのが以前の答えだった。いまは 390px の画面に実際に出るピクセルから決めている。文は 15〜16px、補助の行とラベルは 12〜13px。机の端まで縮んだ紙はもっと小さくてよい——読ませる文ではなく、提案の痕跡だから。

- 縦長の構図では、文字を小さくするのではなくドラフトの用紙を高くした。決定とお客さまの視点では 1.2 倍で前に出る。寄りの画面なので、問い・判断どころ・コントロールが 1 画面すべて読めるサイズになる。
- GoodIdea がまとめ始めた時点から、スマートフォンは一度に一つだけ見せる。統合カード、決定、お客さまの視点。チームの紙、状態の帯、作り手の一言はその 3 つのあいだ脇へ寄り、最後に一緒に戻る。誰の提案かは決定カード自身が書いている。
- 文字つきの 4 段階は、読めるサイズではスマートフォンの上部バーに入らない。いまいる段階だけ名前を出し、残りは番号のままにした。
- CJK の見出しは負のトラッキングを戻し、ブラウザが語句に分けられるところは語句で折り返し、balance を使う。2 つの節からなる文は、語の途中ではなく自分の読点で折り返す。

### 映像の終わり

時計は生の秒で進み、絵は 12fps に量子化した秒から取り出す。両者は終わりで 1 フレーム未満ずれる。「終わったか」を生の秒で尋ねていたので、停止済みの映像でトランスポートは「再生」を出し、読み出しはページが言う長さより 1 秒短かった。いまはどちらもフレームで尋ねる。

## 2026-09-08：AI チームを見えるようにする

主 Demo は約 70 秒の紙のコマ撮り映像になりました（`web/src/studio/paper/`）。フリーランスのデザイナーの見積もりの困りごとがアイデアになり、3 名の専門 Agent が提案を出し、GoodIdea がそれを 1 件の判断にまとめ、作り手が確認してはじめて製品ドラフトが変わり、最後にお客さまの視点が冒頭の 3 つの問いに答えます。尺は脚本から導出（`PAPER_SECONDS`）するので、ページが実在しない秒数を約束することはありません。

- **Agent には識別があり、アバターはない。** 調査 · Mira、UX · Luca、実装 · Kai。役割が先、名前が後。見る人に必要なのは仕事の種類だからです。3 名はそれぞれ 1 色の印（黄土・青灰・茶）を持ち、いずれも GoodIdea 自身のセージから離してあります。作業紙には読める大きさで署名が刷られ、机の端まで縮んだ後は小さな標識が引き継ぎます。人物アイコンの列は追加していません。
- **後の提案は前の提案に答え、それを明示する。** UX は受け取った調査結果の引用から始めます。実装は UX の残した問いを引用し、UX の紙のその行を丸で囲み、より軽い初版を提案します。サイドバーは答えた相手の頭文字で 2 か所を示します。チャットログにはしていません。
- **チームのサイドバーは補助であり、第 3 のパネルではない。** プロジェクト空間 1348 単位のうち 238、5 分の 1 未満。各 Agent は最大 2 行：いま何をしているか、何を提出したか。状態が変わるのは映像が実際にその提案を見せたときだけで、回転も点滅もしません。最下段は GoodIdea 自身の集計で、「着手待ち」から「貢献 3 件 → あなたの決定 1 件」へ。
- **統合は見せるもので、主張ではない。** 署名つきの 3 件が統合エリアに入り、共通する方向、次に判断が要る点が書き出され、そのあとで 1 件の判断がドラフトへ届きます。全体で増えた約 2 秒はここに使い、他の場面を早送りして相殺していません。
- **スマートフォンでも同じ物語で、机を潰した縮小版ではない。** 上部バーの下に簡潔なチーム状態バー、読んでいる紙には完全な署名、統合時は要約カードが画面上半分を占めます。状態バーと作り手の一言はカードに場所を譲り、決定の前に戻ります。お客さま視点では協働の情報を完全にしまい、結末には 3 枚の紙・デザイナー・成果・ブランドが残ります。
- **最初の一枚と、動きを減らす設定。** 自動再生はしません。静止した最初の画面は物語そのものの瞬間——デザイナー、見積書、3 つの問い——であり、空の机ではありません。`prefers-reduced-motion` ではタイムラインを出さず、落ち着いた 10 枚を順に読み、全場面のテキスト版も添えます。
- **映像に Web フォントは同梱しない。** 参考デモの手書きサブセットは自身の中国語しか含まず、英語と日本語では字形が混ざります。手書きの役割はシステムの楷書・明朝スタックに委ね、性格は紙の質感・筆跡・色が担います。
- **素材。** `web/public/paper-film/` に 4 枚のテクスチャを WebP で置いています（合計 456 KB、元の PNG は 7.2 MB）。人物シートはほぼ可逆のままです。透明度を合成時に自身の色から導いているためで、そのフィルタに触れる前に同じディレクトリの `designer-source.md` を読んでください。

映像内の `<footer>` と `<header>` は通常の要素に変えました。ページ全体の `footer` 規則が映像の内部にまで届き、最小高さ 150px と等幅書体を与えていたためです。映像の内部では、ページが指定している裸の要素セレクタを使いません。

## 2026-09-06：1分間のコンセプト映像

主 Demo は60秒の物語になりました。困りごと → 流れが見える → 試作 → 新しい着想 → 初版 → coding agent への引き渡し → 将来の利用場面、最後は探索への問いを残します。以下の旧会話・地図・操作バーの説明は設計履歴として残し、`/lab/?view=story` の詳細版に対応します。

一場面で見せる変化を一つに絞ります。同じお客さまの原文、修正確認リスト、最初の項目の承認が、冒頭と結末をつなぎます。理由の見えない連続操作を、濃い紫の舞台、柔らかい光、つながる線、紙面の試作へ置き換えました。短い入力台詞は三つ。引き渡し後の実装は抽象表現、結末は将来の利用イメージだと明記します。

独立したローカル試作は映像の外に開き、開くと再生が止まります。編集は再生し直しや移動で消えません。静的成果物とダウンロードする Markdown は引き続き `storyCopy` を共用します。連続動作は単一のフレーム時計で管理し、一時停止・非表示で止まり、動きを減らす設定では一場面ずつ進めます。展開できる文字台本からも移動できます。見出し・絵・字幕を分け、中日文の自然な改行を許可して地図との重なりを修正しました。利用者の理解や購入意向はまだ未検証です。

## Design 判断

| 判断 | 実装 | 理由 |
| --- | --- | --- |
| Brand の性格 | Forge の冷たい Engineering Blue から、温かい Violet、Coral、Teal へ変更 | GoodIdea は未完成の Idea を受け止めてから制約する。始めやすさと正直な境界を同時に感じられる必要がある。 |
| Primary Color | 温かい Grape Violet `#7A3F9F` | 以前の Blue Violet は冷たい Surface と大きな Control の上で Blue に見えた。探索/現在の行動という意味を保ちつつ、汎用 SaaS より創造的な印象にする。白文字との Contrast は約 6.91:1。 |
| Semantic Color | Teal `#087B66` は根拠あり/完了、Coral `#BC4637` は境界/注意 | Evidence と Risk を一つの Brand Color に畳まない。色には必ず文言や記号を併記する。 |
| 基礎色 | 背景 `#FFFAF7` と本文 `#241936` | 温かい Surface で Blue の見え方と Audit Console 感を弱めながら、本文約 15.99:1、補助本文約 6.30:1 の Contrast を保つ。 |
| Page の順序 | 用途と読者 → 操作しなくても読める成果物の例 → Demo → 進め方 → 訪問者が握り続けるもの → もう一度体験へ | スクロールしかしない訪問者にも、これは何か・いつ自分に必要か・最後に何が残るか・いま何を試せるか、の四つが答えられなければならない。成果物の例が Demo より前にあるのは、四つのうちそれだけが以前は何度もクリックしないと見えなかったから。 |
| Hero 構成 | 左に明確な約束、右に探索される Map | Map は装飾ではなく主張をする。速そうに見える近道を断りながら、初版の計画にたどり着くまでを見せる。 |
| First View の言葉 | 見出しは仕事そのものを名指す——アイデアを、コーディング AI に渡せる初版の計画にまとめる。Map の Landmark も抽象語ではなく実際の手順を書く | 「根拠 / 判断 / 境界」は過程の形を伝えても、何が手に入るかを伝えない。「アイデアは直線ではない」は一段静かな Brand の一言として残す。 |
| 成果物の例 | 再生の終わりに残るもの——方向・コンセプト試作・初版・引き渡し一式——を静的な一枚に置き、`studio/story/handoffPackage.ts` が再生自身の文言から組み立てる | 百秒見ないと現れない価値は、ほとんどの訪問者には見えない価値。書き直すのではなく `storyCopy` から読み戻すので、三言語のどれでも Page と Demo とダウンロードされる一式が食い違えない。 |
| 見出しの扱い | 見出しは一つの完成した文で、二行に割らず Gradient も持たない | Gradient は「探索から行動へ」という比喩のためのものだった。いまの見出しは具体的な仕事を述べており、行を割ると三言語それぞれ別の位置で切れて、一息で読むことの邪魔になる。 |
| Brand Mark | 角丸 Square の文字 G を、開いた G 型 Path と Coral の Spark に置き換える | 開いた Path は探索の余地がある Idea、Spark は明確な次の一歩へ収束する瞬間を表す。Header、Demo、Footer で同じ Custom Vector を使う。 |
| Action Icon | Scroll と実装を開く操作に、16px の同じ Rounded Stroke の SVG Icon を使う | Font の矢印 Glyph は OS ごとに太さと形が変わる。同じ Stroke System で First View の二つの Action を揃える。 |
| Shape | 12–26px の段階的な角丸 | Engineering Console の距離感を弱め、Control、Content Card、Product Demo の階層を半径で区別する。 |
| Demo の優先度 | Demo は Page 最大の Object のままで、形を変える。会話とアイデアの地図、次に試作が主画面、最後は問いだけ | Feature List より Product Behavior の方が強い証明になる。見せる価値があるのは、アイデアが「触れるもの」になっていくこと。物語ぜんぶを 3 Column の枠に押し込めば、試作が画面で一番小さいものになってしまう。 |
| 見るか、自分で触るか | Demo は読める最初の一往復と二つの入口で開き、Bar はどの状態でも同じ位置と同じ高さに留まる | 要点にたどり着くまでクリックさせるのは、成果物を隠すのと同じ間違い。再生と自分で触る状態は別々で、試作に触れば物語は止まり、触った内容が再生し直しで消えることはない。 |
| 末尾の濃色帯 | 濃色 Panel は理念の宣言ではなく、体験へ戻る導線を担う | Page 後半で最も重い Object は、信条ではなく次の一歩であるべき。以前の原則は「訪問者が何を握り続けるか」を述べた四行に書き直した。 |
| 会話のリズム | Agent の返答は短く、一度に一つの問いだけ進める。自然な選択肢を二つ置き、実際に送信できる自由入力も残す | 訪問者には Form ではなく会話だと分かってほしい。役割名、Avatar、Status Badge は置かない。言葉そのものが Interface で、固定選択肢はこの体験を最後まで歩けるようにするためだけにある。 |
| Concept の状態 | 断片、候補、確定、未検証、置き換え済みを、枠線・不透明度・ごく軽い一行で表す | Badge を並べると Map が Dashboard になる。根拠と仮説は Concept の属性であって独立した欄ではないので、何気なく言ったことが確定した結論に化けない。 |
| 情報量 | Map は一つの Node から始まり、1 ターンにつき目に見える変化は最大一つ。背後の十個の Concept は口に出されて初めて現れる | 空の欄が十個並べば、それは埋めるべき Form になる。方法論は裏に置き、画面に出るのは「ひとつの利用場面ができつつあります」で、「Use Case Unlocked」ではない。 |
| CTA 階層 | 1 View に塗りつぶし Primary Action は一つ | Demo、GitHub、承認、修正が同じ強さで競合しないようにし、次の行動を明確にする。 |
| Motion | Map は一度だけ、5 秒未満で走り、最終状態に留まり、再生し直せる | 多くの訪問者は三秒で判断するため、どの一拍も単独で意味を背負わせず、必要な情報を待ち時間の向こうに置かない。点いたものは二度と消えないので、途中で止まった一枚でも読める。 |
| Reduced Motion | `prefers-reduced-motion: reduce` で Animation、Transition、Smooth Scroll を停止。First View の経路は完成した状態で現れ、Demo は訪問者が自分で送る Step になる | 場面も順序も同じで、外れるのは Timer であって中身ではない。動きを見られる人だけが得られる情報を作らない。 |

| 画像 | 現時点では汎用写真や装飾 Illustration を追加しない | いま最も説得力のある Visual は Interactive Product Behavior。実例が揃ってから Original Visual を検討する。 |

## First View：Idea Map

Map は、何かが読まれる前にこの Page が行う主張です。アイデアが道を進み、速そうな近道に誘われ、そのつど断り、初版の計画にたどり着きます。以下は、次の変更がその理由を偶然に消してしまわないための記録です。

経路は手で拍を打つのではなく Layout から生成します。Desktop は断った近道を三つ、Mobile は一つ見せるので、手書きの拍表はどちらか一方にしか正しくなれません。全体は 5 秒未満で走り切るため、訪問者に必要なものが待ち時間の向こうに置かれることはなく、もう一度見たい人のために再生 Control を図の上に置いています。

**断ることこそが主題なので、三拍に分けます。** アイデアが止まって誤った方へ傾き、その道がまだ明るいうちに標識へ × が付き、そのあとで暗くなり正しい道が点きます。一拍にまとめると判断が見えなくなり、これを Flowchart から隔てている唯一のものが失われます。同じ理由で、誤った標識は透明度を下げて最終画面に残します。狭い画面では三つのうち二つをまるごと落とし、Landmark の意味を述べる一行のほうは落としません。Mobile の読者に「境界」だけを渡して「この版でやらないこと」を渡さないのは、手順ではなく単語を渡したということです。

**殻は運ばれるもので、置かれるものではありません。** 初期版は卵を大きな終点にしましたが、細い線でできた図に貼り付けた立体物のように見えました。今は移動する Token です。始めは無傷、問いに答えるたびにひびが入り、引き渡しで孵ります。孵化の Metaphor は最初からの決定であり、装飾的な形を残すのではなくこの形で保っています。

**環境 Particle は加えません。** この First View の Particle Field は意図して外したものです。名前を変えて漂う粒を戻すのは、同じ装飾に別の Label を付けるだけです。地形はごく淡い不規則な等高線が担います。同心円は Radar に見えるため、意図的に開いていて中心をずらしてあります。

**道の一区間ごとに二層。** 広く柔らかい帯が先に地面を照らし、鮮明な線が後から方向を確定します。単層の線は色が何であれ Chart に見えます。

## Layout を縛るもの

描画は固定の 1000×600 空間にあり、Page が与えた箱に引き伸ばされます。一方 Label は文字サイズの決まった実 DOM です。したがって画面が低いと Landmark 間の Pixel 間隔だけが縮み、Card は縮みません。忘れやすい帰結が二つあります。

- 座標は、Map が取りうる**最も低い**箱と、**最も背の高い**言語に合わせて配置します。後者は中国語ではなく日本語か英語です。
- Map は見出しの背後へ左に滲み出しますが、そこへ行ってよいのは霧と等高線だけです。Label のある Landmark が本文に重なると、読めるものの上に読めるものを置くことになります。

Map の高さは幅だけでなく Viewport の高さにも縛られます。Laptop の画面でも下の Demo Section の上端が見えるようにするためで、その端だけが Page の続きを示す手がかりです。

## Demo：一つの物語を、章ごとに必要な形で

Demo は固定の絵コンテで、背後にエージェントはいません。語るのは一つの物語だけ——一人
で受けているデザイナーが、チャットに散った修正の指示を追えなくなる話——で、サイトは
それ以外を語りません。ページ上の例も、再生の中の例も、ダウンロードできる一式も同じ
一件です。

**レイアウトは通しで固定ではありません。** 最初の二章は会話とアイデアの地図。試作が
現れた時点でそれが主画面になり、会話は一列に退きます。最後の一画面は問いだけです。
三つのレイアウトで高さは一つ：Demo の枠はどれでも同じ高さなので、読んでいる人の下で
ページが動くことはありません。

**地図は育つだけでなく、絞られます。** 四つの配置と、そのあとの流れ：一文、挙がった
事柄の山、見えた問題、そこから立ち上がる製品の形。そして散らばった発見が、四段の道筋
として描き直されます。ノードの文字は実行時に測ります。同じノードが英語では一行、
日本語では二行になるからで、上のノードに重なるものは押し下げられます。

**試作は本当に使えるもので、スクリーンショットではありません。** 同じ修正一覧の両面：
こちらで見直し、相手が一件ずつ確認する。貼り付けたチャットは改行と句点でローカルに
分割され、各項目は元の一文を保持します。ページにもそう書いてあります。「この前のあれ」
が何を指すかを読むのがモデルの要る部分で、このページにモデルはないからです。

**意味のある一往復ごとに、見える変化が一つ返ります。** その変化は画面の動きだけでなく
会話の一行でもあります。スマホでは画面が一タップ先にあり、それでも変化は届く必要が
あるからです。

## 見ること、自分で触ること

Demo には三つの状態があります。読める最初の一往復と二つの入口、再生、そして自分で
触る状態。二つの規則がそれらを分けます。

**再生は導出であって、再演ではありません。** `studio/story/storyScript.ts` が 18 の場面
を組み立て、各場面は差分ではなく画面全体——レイアウト、パネル、地図、試作——を持ちま
す。どの場面の会話も、そこまでの場面の連結です。だから章の見出しから引き渡しへ直接
飛んでも、同じ一往復が二度現れず、画面と文字がずれません。各場面の停留は画面上の文字
から導き、読むものがある拍には余分に取ります。三言語とも通しで 105〜110 秒に収まりま
す。ページに長さを書き込むことはなく、脚本から埋められます。

**タイマーは一つだけで、effect が持ちます。** `studio/autoDemo.ts` はタイマーを含まない
純粋な reducer で、コンポーネントは `setTimeout` を一つだけ張り、状態が変わるたびに
消します。停止後に生き残ったタイマーは reducer 側でも無視されるので、一時停止は入力の
再現も会話もパネルも同時に止めます。バックグラウンドでは中止ではなく保持です。

**自分で触ると、物語は止まります。** 再生中の試作は絵で、フォーカス順に入る操作部は
一つもありません。その上に重なるボタンだけが、再生を止めて操作を渡します。以後、触る
のは訪問者自身の試作の状態で、脚本はそこに書き込みも消去もしません。再生し直しても章
を飛んでも、触った内容はそのまま残り、固定の再生は自分の画面を映し続けます。三つの
方向も同じで、どれを押しても停止し、具体的な答えが返り、同じ画面に戻れます。

`prefers-reduced-motion: reduce` では何もタイマーで進みません。同じ 18 場面が残り、
前へ / 次へと章の見出しになります。内容も順序も変わらず、自動の動きだけが消えます。

## Type Scale

Page は 5 つの Size だけで組む。`web/src/styles.css` に `--fs-tag` から `--fs-lead`
として宣言してあり、6 つ目を勝手に増やさない。

| Token | Size | 用途 |
| --- | --- | --- |
| `--fs-lead` | 17px | Hero の導入文、末尾の濃色帯の本文、Demo で Agent が話す言葉 |
| `--fs-body` | 16px | 既定の本文。段落、List、Idea 入力欄 |
| `--fs-small` | 14px | Caption、注記、左の道標、選択肢、アイデアマップ上の全ての語 |
| `--fs-label` | 13px | 大文字 Monospace の Section Label、Eyebrow、用語 |
| `--fs-tag` | 12px | 大文字 Monospace の Metadata Chip と Status Pill |

**本文は 16px、下限は 14px。** Material 3 は body-large を 16sp、body-medium を 14sp
と定め、読ませる Text をそこで止める。GOV.UK の Scale は 16px を下限とし、小さい画面
でも縮めない方針に変わった。Apple iOS の Body は 17pt。操作 Label も同じ規則に従い、
Button と Navigation は 10px の Monospace ではなく 14〜15px になった。

**12〜13px は全て大文字の Monospace Metadata に限る。** 全て大文字の並びはどの字も
Cap Height なので、12px の Label は 16px の小文字とほぼ同じ Cap Height を持ち、読む
負荷は持たない。これらは 1〜4 語の状態表示であって文ではない。12px 未満で残っている
のは `aria-hidden` の装飾記号だけ。

**Size を上げた分、行間は下げた。** 本文は 1.7、小さい Text は 1.6〜1.75 で、WCAG 2.2
Text Spacing が段落に求める 1.5 を上回りつつ、11px の Text に必要だった 1.85 の緩さを
避けている。

古い Size に合わせて調整されていた 2 箇所は一緒に動かした。First View の 2 つの操作は
横並びをやめて縦に積み、Idea Map は 980px ではなく 1120px から Page 幅いっぱいを取る。

## Accessibility Baseline

- 通常 Text の組合せは WCAG 2.2 の最低 Contrast 4.5:1 に照らして確認する。
- 状態は色だけでなく、文言・番号・Check・境界記号でも示す。
- Keyboard Focus を見えるままにし、Skip Link を保持する。再生/一時停止、もう一度再生、四つの段階 Chip はいずれも Tab 順に入る本物の Button なので、Pointer なしでも Demo を最後まで進められる。
- Motion は OS の Reduced Motion 設定を尊重する。First View の経路は 5 秒未満で終わり、Control が必須になるほど長く動かしてから Control を足す、という順序は取らない。

根拠: [W3C Pause, Stop, Hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)、[W3C Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[W3C Animation from Interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)、[W3C Technique C39](https://www.w3.org/WAI/WCAG22/Techniques/css/C39.html)、[W3C Text Spacing](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)、[Material 3 Type Scale Tokens](https://m3.material.io/styles/typography/type-scale-tokens)、[GOV.UK Type Scale](https://design-system.service.gov.uk/styles/type-scale/)、[Apple HIG Typography](https://developer.apple.com/design/human-interface-guidelines/typography)。
