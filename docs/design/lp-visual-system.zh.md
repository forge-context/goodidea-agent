# GoodIdea LP 视觉系统与设计理由

[English](lp-visual-system.md) | [日本語](lp-visual-system.ja.md) | [中文](lp-visual-system.zh.md)

这份记录说明 LP 当前的视觉决定以及每个决定背后的原因。目标不是证明某种颜色天然代表某种心理，而是建立一套与产品行为一致、可以复用和验证的界面语言。

详细走查与真实工作台共用 `shared/studio/` 中的设计 Token、Studio 样式和地图渲染器；主 Demo 的动画表现独立放在 `web/src/studio/paper/`，类名与自定义属性统一使用 `gip-` 前缀，不改变共用产品界面。

## 2026-09-09（后续）：首屏铺满一屏，并在脚下说出去处

导航是 sticky，但仍占据正常文档空间，所以首屏只需要减一次高度：`--header-h`，桌面 72px、720px 以下 64px。区块用 `min-height: calc(100svh - var(--header-h))`，前面再放一行 `100vh` 给不支持小视口单位的浏览器。用 `svh` 不用 `dvh`——钉在 `dvh` 盒子底部的引导，会在手机工具栏重新出现的一瞬间滑到它下面；用 `min-height` 不用 `height`——矮屏笔记本、放大过的页面、把两半堆起来的手机，都应该把区块撑高而不是把内容裁掉。

文字与插画现在是一整块 `.hero-lead`，在引导占掉自己那一行之后的空间里居中，上留白 8px、下留白 34px，所以这块的视觉重心比几何中心略高一点。没有为了填满高度放大任何东西：左右比例、插画尺寸和上面那三句话都没动。

引导是一个普通链接，去处和上面那个按钮一样。它独占区块最后一行，因此不可能压在插画上；它随首屏一起滚走，而不是跟着页面往下——留下来的引导就变成了控件，而它不是。可见部分距窗口底 28px，另加手机 home 指示条需要的高度。箭头做一次 5px 的缓慢下移再回位，用 `IntersectionObserver` 控制，离开视野即停；`prefers-reduced-motion` 下动画取消，平滑滚动本来就已被页面既有规则退回 `auto`。

锚点加上了 `scroll-margin-top: calc(var(--header-h) + 10px)`。此前页面上每一个站内链接都会落到 sticky 导航下面，这一处同时修好了首屏那两个按钮。

手机上两半堆叠后首屏本身就高于一屏，引导落在区块末尾而不是第一屏底部。这正是需求里的取舍：先保内容可读，不为凑一屏去压缩。

## 2026-09-09：首屏是一张插画，上面写三句话

此前首屏右侧是拼出来的：动画用的纸张纹理、人物图集里的一个姿势、手写的 SVG 线框、一株植物，还有五处按旋转盒子摆放的手写批注。它始终不成立。人物只能露出半个上身，因为纸要盖住精灵图结束的地方；规整的几何线框挨着手绘纸面；批注离撕边太近，读起来像几层各自漂浮的东西。

现在它是一张供稿插画——`web/public/hero/goodidea-hero-illustration.webp`，1374×1145，104 KB——两个人物、主草稿、后层纸张、便签、植物、线框、划掉的一版和绿色圈线都已经在图里。页面不再用 CSS 或 SVG 重画其中任何一样，也不假装这张图有它没有的图层。

**图片不是透明的，也不需要是。** 它的底色是 `#faf8f2`，页面的 `--paper` 是 `#fbf8f2`。在 1440×900 的渲染截图上跨四条边采样，最大差值是红通道的一步——没有需要遮掩的矩形，因此不加遮罩、不加混合模式。混合模式是那个看起来省事的做法，也是错的：它会为了盖住一条没人看得见的边，去改人物和纸张的颜色。

**文字是 DOM，因为这张画要服务三种语言。** 素材特意不带文字。三句话叠在上面，位置都是相对图片的百分比，角度按各自下方纸面的走向分别定，全部从素材上实测：顶部长绿线从 (31.3%, 25.6%) 到 (69.1%, 31.2%)，所以上面的标题转 +7°；椭圆中心 (70.8%, 53.8%)、半径 13.1% 与 10.25%，里面那句几乎不转；底部短线是 -3°。给三处套同一个旋转值，至少有两处会和它所属的那条线明显错开。

**圈内那句的换行写在文案里。** 椭圆只有中间一段是宽的，按宽度排的文字块永远会把首行和末行顶出曲线。三种语言各自带自己的换行，并逐一核对块角到椭圆的归一化距离：0.77、0.61、0.66，都在圈内。

**45 / 55，以及一个撑得起自己那半边的标题。** 插画是更宽的那一半，标题是更重的那一半；大插画配小字，会被读成一张海报加一句说明。标题上限从 42px 提到 53px；中日文标题改为在文案里「一句一行」，因为 `word-break: auto-phrase` 只在 Chrome 生效且不切分中文——此前它把「可以」和「着手できる」从中间断开。英文仍是一整句，在列宽处自然换行。

**运动只有 16px，而且是一个整体。** 图片和三句话在同一个被变换的元素里，不可能互相脱开；不加旋转，因为把一张矩形的、带底色的图转起来，恰好就会露出它的边。滚动只写一个自定义属性，其余交给 CSS，滚动过程中没有组件状态变化；离开可视区、手机端与 `prefers-reduced-motion` 下完全停止。手机上只保留标题：另外两句在那个宽度下会低于页面自己的可读字号下限。

## 2026-09-08（后续）：统一页面语言，Demo 提前

页面同时带着三套视觉：紫粉营销皮肤、里面鼠尾草绿的纸面动画，以及深紫结尾条；阅读顺序又要求访客先读完七张成果卡，才看到解释它们的东西。这两件事现在统一了。

- **一套配色，定义在 `web/` 内。** 暖白底、石墨字，主要操作使用足够深的鼠尾草绿。浅绿只用于选中、提案和轻量强调；研究赭色、UX 蓝灰、工程棕色保持专业身份语义，不扩大为每个区块一种颜色。外层紫色光晕、紫色说明框、深紫渐变结尾全部移除。语义变量在 `web/src/styles.css` 内覆盖，不改 `shared/studio/`，私有产品消费者不受影响。
- **一个标志。** 官网现有的 G 路径现在同时用于页头、页脚、动画里的工作区顶栏、GoodIdea 自己的综合卡与片尾；动画内那个斜体小写 `g` 已移除。一个形状、一套配色、三种尺寸。
- **界面只用一种字体。** 正文、导航、状态、决策卡与全部控件都是系统无衬线。手写体只留给想法原句、真实批注和笔迹。
- **顺序：定位 → 主 Demo → 完整成果 → 协作机制与决定权 → 简洁结尾。** 动画是论据，首屏和它之间不再堆东西。首屏改为一块简短的动态面板：三份署名贡献汇入、GoodIdea 综合、一项由你决定、产品稿逐渐成形——表达产品本身的形状，不是具体案例。案例只在下方 Demo 与成果区展开；放在首屏时，它的标题和价格会让页面被读成一个报价工具的官网。面板只跑一次就停住，不是旧的路线图，也不循环。
- **成果是一份产品稿加两组边界。** 一张主稿承载最初那句话、产品方向与概念草图；旁边是第一版做什么、不做什么；展开区里才是验收条件、待验证假设与实现任务。没有任何必要边界被藏进折叠。
- **协作机制与决定权合成一个区块。** 三步写具体行为，下面三条原则。产品愿景（在地图里修改、在原型里提要求）明确写成目标，因为当前公开动画没有这些交互。
- **边界说明完整地说一次，放在结尾。** 播放器旁保留简短的「概念动画 · 固定示例」，待验证内容旁保留有上下文的提示，但整段不再逐区复述。

### 决策卡，和按下它的鼠标

按钮此前脱离了提出问题的那张卡：挂在稿面底边，和说明之间隔着大块空白；模拟鼠标又瞄准一个与按钮分开写死的坐标——箭头尖端落在按钮上方几个像素，按下时按钮还会往下移，离得更远。

- 按钮现在是决策卡内部的最后一项，走正常文档流，顺序为：待你决定 → 提案标题 → 简短说明 → 本轮暂不做什么 → 贡献来源 → 采用按钮。三种语言下都留有底部安全间距。
- 鼠标不再携带坐标。时间轴只说它要去哪个控件、走到几成；舞台从实际布局出来的框里解析这两端，并经过纸张自身的变换。箭头尖端（24 单位精灵里的 4, 2）是唯一热点：精灵按它定位，按压以它为原点缩放，波纹以它为圆心。
- 每一处落在句子上的笔迹——划掉旧描述的删除线、研究结论的下划线、圈出待议问题的圆圈——都由该句实际占据的框生成，长语言下文字和笔迹一起移动。此前删除线只划掉两行中的一行，英文下划线画到三分之二就停了。
- 移动过程比它对应的节拍早一帧结束，所以「到达」那一帧鼠标已经稳稳停在控件上，而不是还在伸手。

### 手机一次只读一块

此前的做法是把 760 单位舞台整体缩小，然后当成可读。现在尺寸从 390px 屏幕上真实呈现的像素反推：正文 15–16px，次要说明与标签 12–13px。缩到桌面外围的纸可以更小，因为它是贡献的痕迹，不承担必读文字。

- 窄屏给产品稿更高的纸，而不是更小的字；决策与客户视角时它前移到 1.2 倍，做成近景——问题、取舍与按钮在同一屏内都达到阅读尺寸。
- 从 GoodIdea 开始综合起，手机一次只呈现一块：融合卡、决策、客户视角。团队的纸、状态条与创作者的念头一起让位，最后一起回来；决策卡自己写明三位贡献者。
- 四个带文字的阶段在手机顶栏放不下，于是只有当前阶段有名字，其余保留序号。
- 中日文标题取消负字距，能分词时按词组换行，并使用 balance——两个分句的句子会在自己的逗号处断开，而不是从词中间断。

### 播放结束

时钟走的是原始秒，画面取自 12fps 量化秒，两者在片尾相差不到一帧。用原始秒判断「是否结束」，导致播放已经停止但主按钮还写着「播放」，读数也比页面宣称的时长少一秒。现在两处都按帧判断。

## 2026-09-08：让 AI 团队看得见

官网 Demo 改为约 70 秒的纸面定格动画，实现在 `web/src/studio/paper/`。自由职业设计师的报价困扰变成一个想法；三位专业 Agent 各交出贡献；GoodIdea 把它们综合成一项待决定；创作者确认之后，产品稿才改写；客户视角回答开头那三个问题。时长由剧本派生（`PAPER_SECONDS`），页面不可能写出动画并不成立的数字。

- **Agent 有身份，不是头像。** 研究 · Mira、UX · Luca、工程 · Kai。角色在前、名字在后，因为观众要看的是哪一类工作。三人各用一种标记色（赭石、青灰、棕），都避开 GoodIdea 自己的鼠尾草绿，系统与团队不会读成同一个声音。纸张上以可读字号印着署名；缩到桌面外围后，由小标记接手。没有新增一圈人物头像。
- **后来的贡献会回应先前的，并且说出来。** UX 开场就引用它承接的研究发现。工程引用 UX 留下的问题，在 UX 自己的纸上圈出那一行，改为提议更轻的第一版。协作栏用被回应者的首字母标出这两处。没有变成聊天记录。
- **协作栏是辅助，不是第三块面板。** 占项目空间 1348 单位中的 238，不到五分之一。每位 Agent 最多两行：当前在做什么、已交出什么。状态只在动画真的展示了那份贡献时才变化，不旋转、不闪烁；最下面一行是 GoodIdea 自己的计数，从「等待团队接手」到「3 份贡献 → 1 项待你决定」。
- **综合是演出来的，不是断言。** 三份署名贡献进入融合区，先写出共同方向，再写出待取舍项，然后才有一项决定送到产品稿。全片增加的约 2 秒都花在这里，其余段落没有为此加速。
- **手机是同一个故事，不是压扁的桌面。** 顶栏下一条紧凑团队状态条；当前阅读的那张纸显示完整署名；融合时展开一张摘要卡占据上半屏——状态条和创作者的念头为它让位，并在决定之前回来。客户预览阶段完全收起协作信息；结尾保留三张纸、设计师、成果与品牌。
- **首帧与减少动态效果。** 动画不自动播放，静态首帧是故事本身的时刻——设计师、报价单、三个提问——而不是空桌面。开启 `prefers-reduced-motion` 时没有时间轴：十张已定格的画面逐段阅读，另有全部段落的文字版。
- **动画不附带网页字体。** 参考小样的手写字体子集只覆盖它自己的中文，英日会出现半数字符回退的混排。手写角色改用系统楷体 / 明朝体栈兜底，纸面纹理、笔迹与颜色承担性格。
- **素材。** `web/public/paper-film/` 存放四张纹理的 WebP（共 456 KB，原 PNG 为 7.2 MB）。人物图集接近无损，因为它的透明度是在合成时从自身颜色推导出来的——改这个滤镜前请先看同目录的 `designer-source.md`。

动画内部的 `<footer>` 与 `<header>` 已改为普通元素：官网全局的 `footer` 规则曾伸进动画，给它加上 150px 最小高度和等宽字体。动画内部不再使用官网会命中的裸元素选择器。

## 2026-09-06：主 Demo 改为一分钟概念动画

此前详细走查的操作过多，观众难以理解变化的原因。官网入口现在使用 60 秒动画：一个困扰 → 想法成形 → 看见原型 → 再向前一步 → 定下第一版 → 交给 coding agent → 做成之后，最后停在邀请探索的留白。以下旧版对话、地图和控制条细节仍作为设计履历保留，适用于 `/lab/?view=story` 中的详细走查。

- 每幕只强调一个变化。客户原话、同一份修改确认单、首条修改的确认与回写贯穿故事；不再模拟一连串没有解释的点击。
- 画面是深紫舞台、柔和光晕、流动连线与纸面原型，重点内容保持真实可读。交接后的实现只作抽象表达，并标注未来使用情境。
- 主线只保留三句简短逐字台词；静态产出与 Markdown 下载仍从 `storyCopy` 读取完整方案，动画压缩表现而不另造一份事实。
- 独立原型在观看区域外展开。打开时暂停播放，编辑不受重播或跳转影响，保留原有客户可见边界及重新确认规则。
- 单一 `requestAnimationFrame` 时间轴管理所有连续动效。暂停、后台与减少动效设置不会让画面偷偷前进；减少动效改为逐幕阅读，另提供可展开的文字脚本和跳转。
- 标题、主视觉和字幕分区；卡片内文字自然排版。中日文标题允许自然换行，修正桌面长句伸进地图、手机卡片撑出画面的问题。
- 不自动承诺转化或已实装功能；这仍是固定的概念演示。真人理解、阅读节奏与购买意愿需要后续验证。

## 核心概念

GoodIdea 的产品过程是“发散想法 → 查证现实 → 收敛边界 → 产生行动”。因此，界面要同时具备两种气质：让人愿意开始探索，也让人相信系统会在关键处停下来。

## 设计决定

| 决定 | 实装 | 原因 |
| --- | --- | --- |
| 品牌气质 | 从 Forge 风格的冷蓝工程界面改为温暖的紫、珊瑚和青绿 | GoodIdea 不是审计工具。它先接住还不完整的想法，再逐步收敛；更有温度的色彩能把“可以开始”与“有边界”同时表达出来。 |
| 主色 | 暖葡萄紫 `#7A3F9F` | 原来的蓝紫在冷白背景和大面积按钮中容易被看成蓝色。暖葡萄紫仍表示“探索/当前行动”，但更贴近创意产品，而不是通用 SaaS 或工程工具。白字对比度约为 6.91:1。 |
| 辅助色 | 青绿 `#087B66` 表示证据成立或完成；珊瑚 `#BC4637` 表示边界或需要注意 | 把正向证据与风险边界分开，避免所有状态都挤在同一种品牌色中。颜色同时配有文字、符号或标题，不依靠色觉单独传递信息。 |
| 背景与正文 | 暖白 `#FFFAF7` 配深紫黑 `#241936` | 暖白减少主色被视觉感知为蓝色的倾向，也降低工程工具的冷硬感。正文对比度约为 15.99:1，弱化正文约为 6.30:1。 |
| 页面顺序 | 用途与受众 → 不用操作也能读的产出示例 → Demo → 工作方式 → 你保留的控制 → 再次进入体验 | 只滑不点的访客要能回答四件事：这是做什么的、什么情况下适合我、最后得到什么、现在可以怎么体验。产出示例排在 Demo 之前，因为四件事里只有它以前需要点很多次才看得到。 |
| Hero 构图 | 左侧是承诺，右侧是一张被探索的地图 | 地图在论证，不在装饰：一个想法先后拒绝看起来更快的捷径，才变成可以动手的东西。装饰性的粒子场好看，但没有说出产品做什么。 |
| 首屏语言 | 标题直接说事情本身——把想法整理成可以交给编程 AI 的第一版方案；地图节点写具体步骤，不写抽象名词 | 「证据 / 决定 / 边界」告诉访客流程的形状，却没告诉他会拿到什么。原来的「想法不是直线」保留为低一级的品牌短句。 |
| 产出示例 | 一页静态的最终产出——产品方向、概念原型、第一版定义与交接材料——由 `studio/story/handoffPackage.ts` 从演示自己的文案组装 | 要看一百秒才出现的价值，多数访客根本看不到。从 `storyCopy` 读回来而不是另写一份，三种语言下页面、Demo 和可下载的交接包都不会各说各话。 |
| 标题表现 | 主标题是一句完整的话，不再拆成两行、也不再套渐变 | 渐变原本服务的是「探索到行动」这句比喻。现在标题说的是具体的事，拆行和渐变只会在三种语言里各断一次行，反而妨碍它被一眼读完。 |
| 品牌标记 | 用“未闭合的 G 路径 + 珊瑚色亮点”替代圆角方块里的字母 G | 未闭合路径代表想法仍有探索空间，亮点代表它收敛为明确下一步的瞬间。页头、Demo 和页脚复用同一个专属矢量标记。 |
| 操作图标 | 向下浏览和打开实现统一使用 16px 圆角线条 SVG | 字体箭头在不同系统中粗细和形状不一致。统一线宽能让首屏两个操作看起来属于同一套设计语言。 |
| 卡片形状 | 使用 12–26px 的分层圆角，不使用完全方正面板 | 圆角降低“审计控制台”的距离感；不同层级使用不同半径，帮助区分按钮、内容卡和大型产品 Demo，而不是随意装饰。 |
| Demo 地位 | Demo 仍是页面最大的实体，而且会变形：先是对话加想法地图，然后原型占据主画面，最后只剩一个问题 | 访问者应先看到产品行为，而这里值得展示的行为是“想法变成能点的东西”。把整个故事关在三栏框里，原型就会成为屏幕上最小的一块。 |
| 观看或自己探索 | Demo 默认停在可读的第一轮，给出两个入口；控制条在所有状态下位置和高度都不变 | 让访客点半天才看到重点，和把产出藏起来是同一个错误。播放与探索是两份互不写入的状态：动原型就会暂停故事，访客试过的内容也不会被重播抹掉。 |
| 页尾深色块 | 深色面板现在承载「回到体验」，不再承载理念宣言 | 页面下半部分最重的一块应该是下一步，而不是一段信念。原来的原则改写成四条关于「你保留什么控制」的白话。 |
| 对话节奏 | Agent 回复很短，一次只推进一个问题；给两个自然的回答，同时保留真的能发送的自由输入 | 访问者应该认出这是一段对话，不是一份问卷。不出现角色名、头像和状态 Badge：话本身就是界面，固定选项只是让这段体验能走完。 |
| 概念状态 | 碎片、候选、确认、待验证、已改变，由边框、透明度和一行很轻的文字共同表达 | 大量 Badge 会把地图变成 Dashboard。证据与假设是节点的属性，不是独立栏目，Agent 也就无法把用户随口说的话包装成确定结论。 |
| 信息密度 | 地图从一个节点开始，每轮最多出现一个明显变化；后台的十个概念只有被说出来之后才出现 | 十个空栏目就是一张待填表格。方法论留在后台，用户看到的是“一个使用场景正在成形”，而不是“Use Case Unlocked”。 |
| CTA 层级 | 每屏只有一个实心主操作，次操作使用白底或文本形式 | 明确下一步，防止“试 Demo”“看 GitHub”“修改提案”等动作在视觉上相互竞争。 |
| 动效 | 地图只播放一次，五秒以内跑完，停留在最终状态，并提供重播 | 多数访客三秒内就决定是否继续，所以任何单独一拍都不能承担全部信息，访客需要的东西也不能藏在等待后面。已经点亮的东西不会再变暗：任何一帧被打断，画面本身都读得懂。 |
| 减少动态效果 | `prefers-reduced-motion: reduce` 下关闭动画、平滑滚动和过渡；首屏路线直接呈现完成状态，演示变成访客自己按的步骤 | 场景和顺序一模一样，被去掉的是计时器而不是内容。任何信息都不应只有「看得到动画」的人才拿得到。 |
| 响应式 | 桌面按幕切换两栏比例；手机上前两章对话就是页面、地图收进面板，原型登场后画面在上、对话缩为最近一两条并可整段展开 | 保留各尺寸下的阅读顺序和核心操作，不只是把桌面版等比例缩小。手机上宁可让原型滚动，也不把它缩到读不清。 |
| 手机阅读顺序 | 首屏路线改为两列、从上往下走，保留每个节点那句解释，只保留三条岔路中的一条 | 原来的紧凑路线是向上爬的，向下滑动会先遇到结果、再遇到得出结果的过程；而且它是靠删掉解释来省高度的。要压缩时，含义是最后才动的东西。 |
| 内容列宽 | `--shell` 在笔记本宽度内保持 1180px，之后随视口增长，上限 1360px；所有区块共用同一条边 | 固定 1180px 时，1920px 显示器上约四成是空白。上限由 Demo 决定：超过 1360px 后对话气泡已经达到可读行长，多出来的宽度只会把想法输入框和主操作拉长。 |
| 字体 | 三种语言使用各自的系统字体栈，大标题统一采用真实存在的 600 字重，等宽字体只保留给真正的技术元数据 | 页面不再依赖实际没有加载的 Inter。中文标签使用中文字体度量，移除只适合拉丁文的大写和字距规则，并设置语义换行点，避免把“开始”这类词从中间拆开。 |
| 字号阶梯 | 一套五级字号：正文 16px，引导文 17px，凡是成词成句的文字下限 14px，12–13px 只留给全大写等宽的元数据 | 改版前几乎所有文字都在 8–13px，低于任何一套主流设计基准。 |
| 图像策略 | 当前不增加无关照片或抽象插画 | 现阶段最有说服力的视觉是可交互产品行为。等品牌资产和真实案例成熟后，再评估是否需要原创视觉，而不是用库存图分散焦点。 |

## 首屏：想法地图

地图是页面在被阅读之前就已经做出的论证。一个想法沿路线前进，被看起来更快的捷径吸引，逐一拒绝，最后到达一份第一版方案。下面这些记录的目的，是让后续改动不会顺手撤掉这些理由。

路线由布局生成，不再手写节拍表：桌面显示三条被拒绝的捷径，手机只显示一条，手写的节拍表最多只能对其中一种是对的。整段跑完在五秒以内，访客需要的东西不会藏在等待后面；画面上另有一个重播控件，供想再看一遍的人使用。

**拒绝本身才是重点，所以它占三拍。** 想法停住并向错误方向倾斜；路牌被打上叉，而那条路仍然明亮；然后它才变暗，正确的路才亮起。把这三步压成一拍，那个决定就看不见了——而它正是这张图和流程图之间唯一的区别。同理，错误路牌在最终画面上保留（降低透明度）；窄屏上直接去掉三条中的两条，而不是去掉节点那句解释。只给手机读者「边界」而不给「这一版不做什么」，给的是一个词，不是一个步骤。

**蛋是被带着走的，不是停在终点的。** 早期版本把蛋做成大型终点，结果它像是贴在一张细线条图上的立体物件。现在它是那枚移动的 Token：起点完整，每回答一个问题裂开一道，到交接时孵化。孵化的隐喻是最初就定下的决定，用这种方式保留，而不是靠留下一个装饰形状。

**不要加环境颗粒。** 这个首屏上原本的粒子场是被刻意移除的。换个名字把漂浮颗粒加回来，是同一种装饰换了标签；地形由极淡的不规则等高线承担。那些等高线刻意开放且偏心，因为同心圆会读成雷达。

**每段路线两层。** 先由宽而柔的光带照亮地面，再由清晰实线确认方向。单层线条无论什么颜色，都会读成图表。

## 布局受什么约束

绘图活在固定的 1000×600 坐标空间里，被拉伸到页面给它的任何盒子中；而标签是真实 DOM，字号固定。所以屏幕变矮时，地标之间的像素间距会缩，卡片却不会。两个容易忘记的后果：

- 坐标是按地图允许的**最矮**盒子、以及**最高**的语言来排的——那是日文或英文，不是中文。
- 地图向标题背后延伸，但只有雾和等高线可以过去。带标签的地标压在文案上，等于把可读的东西盖在可读的东西上。

地图高度同时受视口高度约束，这样在笔记本屏幕上，下方 Demo 区块的顶边仍然露出来。那条边是页面还有内容的唯一提示。

## Demo：一个故事，每一章用它需要的形状

Demo 是固定分镜，背后没有 Agent。它只讲一个故事——一个人接单的设计师，想把客户散在
聊天里的修改意见理清楚——官网也不讲第二个，所以页面上的示例、演示里的示例和可下载
的交接包，说的是同一件事。

**布局不是全程固定的。** 前两章是对话加想法地图；原型一出现就占据主画面，对话退到
一列；最后一屏只剩一个问题。三种布局共用一个高度：Demo 窗口在三种布局里一样高，正在
阅读的人不会被它下面的内容顶动。

**地图会收敛，而不只是长大。** 四个排布加一条流程：一句话、被提到的一堆事、看清的
问题、由此长出的产品样子，然后零散的发现被重画成一条四步的路线。节点文字在运行时
测量，因为同一个节点在英文里是一行、日文里是两行，会压到上面节点的都会被推开。

**原型是真的可以用的，不是截图。** 同一份修改项的两面：设计师校对，客户逐项确认。
粘进来的聊天在本地按换行和句号切分成修改项，每一条都留着它来自的那句话——页面上写
明了这一点，因为看懂「上次说的那个」指什么才是需要模型的部分，而这个页面没有模型。

**每一次值得的对话都兑现一个看得见的变化**，而且这个变化是对话里的一行，不只是画面
上的一次移动：手机上画面在一次点击之外，变化仍然要读得到。

## 观看它，和自己探索

Demo 有三个状态：可读的第一轮加两个入口、播放、自己探索。两条规则把它们分开。

**播放是推导出来的，不是重放。** `studio/story/storyScript.ts` 生成十八幕，每一幕带的
是整个画面——布局、面板、地图和原型——而不是一次改动。任何一幕的对话，就是前面各幕
连起来。这样章节跳转可以直接到交接，不会有哪一轮出现两次，画面和文字也不会脱节。每
一幕的停留由屏幕上的文字推导，需要阅读的几拍额外留时间，三种语言整段落在一百零五到
一百一十秒之间。页面上从不写死时长，由脚本填入。

**只有一个计时器，由 effect 持有。** `studio/autoDemo.ts` 是不含计时器的纯 reducer；
组件只装一个 `setTimeout`，任何状态变化都会清掉它。暂停之后仍然到期的计时器也会被
reducer 忽略，所以暂停会同时停住逐字输入、对话和面板。切到后台是停住而不是取消。

**探索会停住故事，而不是和它抢画面。** 播放期间原型是一张图，没有任何控件进入焦点
顺序，只有覆盖其上的一个按钮：按下就暂停播放并把控制权交给访客。之后访客操作的是自己
那一份原型状态，脚本既不写入也不清空它：重播或跳章之后，他试过的内容还在原处，而固定
演示照旧显示自己的画面。三条方向也一样——点任意一条都会暂停、给出具体反馈，并能回到
同一个画面。

在 `prefers-reduced-motion: reduce` 下没有任何东西靠计时器推进。同样的十八幕保留，
改为上一步 / 下一步加章节跳转，内容与顺序不变，去掉的只是自动的动。

## 字号阶梯

整页只用五级字号，在 `web/src/styles.css` 中声明为 `--fs-tag` 到 `--fs-lead`，不再
另外发明第六级。

| Token | 字号 | 用途 |
| --- | --- | --- |
| `--fs-lead` | 17px | 首屏引导文、页尾深色块的正文，以及 Demo 里 Agent 说的话 |
| `--fs-body` | 16px | 默认正文：所有段落、列表和想法输入框 |
| `--fs-small` | 14px | 图注、附注、左侧路标、回答选项，以及想法地图上的所有文字 |
| `--fs-label` | 13px | 全大写等宽的区块标签、眉题和术语 |
| `--fs-tag` | 12px | 全大写等宽的元数据标签与状态药丸 |

**正文 16px，下限 14px。** Material 3 把 body-large 定为 16sp、body-medium 定为
14sp，可读文本到此为止；GOV.UK 的字号阶梯最小值是 16px，并且已经明确不再在小屏上
缩小；Apple iOS 的 Body 是 17pt。可交互的标签遵循同一条规则，所以按钮和导航从原来
的 10px 等宽提高到 14–15px。

**12–13px 只允许用于全大写等宽的元数据。** 全大写序列里每个字形都是大写高度，因此
12px 的标签大致相当于 16px 小写文本的大写高度，却不承担阅读负担——它们是一到四个词
的状态标记，不是句子。页面上小于 12px 的只剩几个 `aria-hidden` 的装饰符号。

**字号变大之后行高相应收紧。** 正文行高 1.7，小字 1.6–1.75，既高于 WCAG 2.2 文本间距
对段落要求的 1.5，又避免了 11px 文字才需要的 1.85。

有两处版式原本是按旧字号调过的，这次一起改：首屏两个操作改为上下堆叠而不是并排；
想法地图从 1120px 起就占满页面宽度，而不是 980px。

## 可访问性基线

- 普通文本颜色组合按 WCAG 2.2 的 4.5:1 最低对比度检查；大文本不能成为降低普通正文对比度的借口。
- 状态不只用颜色表示，也使用文字、编号、勾选或边界符号。
- 键盘焦点使用可见的外轮廓，页面保留跳过导航链接。播放、暂停、重播和四个阶段标签都是真正的
  按钮并进入 Tab 顺序，不用鼠标也能把演示走完。
- 动效遵从系统的减少动态效果偏好；首屏路线在五秒内跑完并提供重播控件，而不是长到必须提供
  控件才合规。

设计依据：[W3C Pause, Stop, Hide](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)、[W3C 对比度最低要求](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[W3C Animation from Interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)、[W3C `prefers-reduced-motion` 技术 C39](https://www.w3.org/WAI/WCAG22/Techniques/css/C39.html)、[W3C 文本间距](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)、[Material 3 字号阶梯](https://m3.material.io/styles/typography/type-scale-tokens)、[GOV.UK 字号阶梯](https://design-system.service.gov.uk/styles/type-scale/)、[Apple HIG 字体规范](https://developer.apple.com/design/human-interface-guidelines/typography)。
