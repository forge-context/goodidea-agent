# GoodIdea LP 视觉系统与设计理由

[English](lp-visual-system.md) | [日本語](lp-visual-system.ja.md) | [中文](lp-visual-system.zh.md)

这份记录说明 LP 当前的视觉决定以及每个决定背后的原因。目标不是证明某种颜色天然代表某种心理，而是建立一套与产品行为一致、可以复用和验证的界面语言。

## 核心概念

GoodIdea 的产品过程是“发散想法 → 查证现实 → 收敛边界 → 产生行动”。因此，界面要同时具备两种气质：让人愿意开始探索，也让人相信系统会在关键处停下来。

## 设计决定

| 决定 | 实装 | 原因 |
| --- | --- | --- |
| 品牌气质 | 从 Forge 风格的冷蓝工程界面改为温暖的紫、珊瑚和青绿 | GoodIdea 不是审计工具。它先接住还不完整的想法，再逐步收敛；更有温度的色彩能把“可以开始”与“有边界”同时表达出来。 |
| 主色 | 暖葡萄紫 `#7A3F9F` | 原来的蓝紫在冷白背景和大面积按钮中容易被看成蓝色。暖葡萄紫仍表示“探索/当前行动”，但更贴近创意产品，而不是通用 SaaS 或工程工具。白字对比度约为 6.91:1。 |
| 辅助色 | 青绿 `#087B66` 表示证据成立或完成；珊瑚 `#BC4637` 表示边界或需要注意 | 把正向证据与风险边界分开，避免所有状态都挤在同一种品牌色中。颜色同时配有文字、符号或标题，不依靠色觉单独传递信息。 |
| 背景与正文 | 暖白 `#FFFAF7` 配深紫黑 `#241936` | 暖白减少主色被视觉感知为蓝色的倾向，也降低工程工具的冷硬感。正文对比度约为 15.99:1，弱化正文约为 6.30:1。 |
| Hero 构图 | 左侧是承诺，右侧是一张被探索的地图 | 地图在论证，不在装饰：一个想法先后拒绝三条看起来更快的捷径，才变成可以动手的东西。装饰性的粒子场好看，但没有说出产品做什么。 |
| 标题表现 | 主标题第二行使用紫到珊瑚的有限渐变 | 渐变把探索到行动的转变压缩为一个视觉线索，只用于大标题，不用于正文和按钮，避免牺牲可读性或形成视觉噪声。 |
| 品牌标记 | 用“未闭合的 G 路径 + 珊瑚色亮点”替代圆角方块里的字母 G | 未闭合路径代表想法仍有探索空间，亮点代表它收敛为明确下一步的瞬间。页头、Demo 和页脚复用同一个专属矢量标记。 |
| 操作图标 | 向下浏览和打开实现统一使用 16px 圆角线条 SVG | 字体箭头在不同系统中粗细和形状不一致。统一线宽能让首屏两个操作看起来属于同一套设计语言。 |
| 卡片形状 | 使用 12–26px 的分层圆角，不使用完全方正面板 | 圆角降低“审计控制台”的距离感；不同层级使用不同半径，帮助区分按钮、内容卡和大型产品 Demo，而不是随意装饰。 |
| Demo 地位 | 保持 Demo 为页面最大的实体：中间对话，右侧是跟着对话生长的想法地图，左侧只有安静的路标 | 访问者应先看到产品行为，而这里值得展示的行为是“想法被理解”，不是“报告被生成”。视觉权重依次是中间、右侧、左侧。 |
| 对话节奏 | Agent 回复很短，一次只推进一个问题；给两个自然的回答，同时保留真的能发送的自由输入 | 访问者应该认出这是一段对话，不是一份问卷。不出现角色名、头像和状态 Badge：话本身就是界面，固定选项只是让这段体验能走完。 |
| 概念状态 | 碎片、候选、确认、待验证、已改变，由边框、透明度和一行很轻的文字共同表达 | 大量 Badge 会把地图变成 Dashboard。证据与假设是节点的属性，不是独立栏目，Agent 也就无法把用户随口说的话包装成确定结论。 |
| 信息密度 | 地图从一个节点开始，每轮最多出现一个明显变化；后台的十个概念只有被说出来之后才出现 | 十个空栏目就是一张待填表格。方法论留在后台，用户看到的是“一个使用场景正在成形”，而不是“Use Case Unlocked”。 |
| CTA 层级 | 每屏只有一个实心主操作，次操作使用白底或文本形式 | 明确下一步，防止“试 Demo”“看 GitHub”“修改提案”等动作在视觉上相互竞争。 |
| 动效 | 地图只播放一次，约六秒半，并永久停留在最终状态 | 多数访客三秒内就决定是否继续，所以任何单独一拍都不能承担全部信息。已经点亮的东西不会再变暗：任何一帧被打断，画面本身都读得懂。 |
| 减少动态效果 | `prefers-reduced-motion: reduce` 下关闭动画、平滑滚动和过渡 | 系统偏好减少动态效果的用户应得到同样完整的信息。静态界面不依赖动画才能理解。 |
| 响应式 | 桌面三栏；1080px 以下左侧折叠成顶部阶段提示，保留对话与地图两栏；手机上对话就是页面，探索与想法地图成为两个真实面板 | 保留各尺寸下的阅读顺序和核心操作，不只是把桌面版等比例缩小。地图宁可滚动，也不缩到读不清。 |
| 内容列宽 | `--shell` 在笔记本宽度内保持 1180px，之后随视口增长，上限 1360px；所有区块共用同一条边 | 固定 1180px 时，1920px 显示器上约四成是空白。上限由 Demo 决定：超过 1360px 后对话气泡已经达到可读行长，多出来的宽度只会把想法输入框和主操作拉长。 |
| 字体 | 三种语言使用各自的系统字体栈，大标题统一采用真实存在的 600 字重，等宽字体只保留给真正的技术元数据 | 页面不再依赖实际没有加载的 Inter。中文标签使用中文字体度量，移除只适合拉丁文的大写和字距规则，并设置语义换行点，避免把“开始”这类词从中间拆开。 |
| 字号阶梯 | 一套五级字号：正文 16px，引导文 17px，凡是成词成句的文字下限 14px，12–13px 只留给全大写等宽的元数据 | 改版前几乎所有文字都在 8–13px，低于任何一套主流设计基准。 |
| 图像策略 | 当前不增加无关照片或抽象插画 | 现阶段最有说服力的视觉是可交互产品行为。等品牌资产和真实案例成熟后，再评估是否需要原创视觉，而不是用库存图分散焦点。 |

## 首屏：想法地图

地图是页面在被阅读之前就已经做出的论证。一个想法沿路线前进，三次被看起来更快的捷径吸引，三次拒绝，最后到达可以动手的地方。下面这些记录的目的，是让后续改动不会顺手撤掉这些理由。

**拒绝本身才是重点，所以它占三拍。** 想法停住并向错误方向倾斜；路牌被打上叉，而那条路仍然明亮；然后它才变暗，正确的路才亮起。把这三步压成一拍，那个决定就看不见了——而它正是这张图和流程图之间唯一的区别。同理，三条错误路牌在最终画面上保留（降低透明度），窄屏上先砍掉主节点的说明，再考虑砍岔路的那句。

**蛋是被带着走的，不是停在终点的。** 早期版本把蛋做成大型终点，结果它像是贴在一张细线条图上的立体物件。现在它是那枚移动的 Token：起点完整，每回答一个问题裂开一道，到交接时孵化。孵化的隐喻是最初就定下的决定，用这种方式保留，而不是靠留下一个装饰形状。

**不要加环境颗粒。** 这个首屏上原本的粒子场是被刻意移除的。换个名字把漂浮颗粒加回来，是同一种装饰换了标签；地形由极淡的不规则等高线承担。那些等高线刻意开放且偏心，因为同心圆会读成雷达。

**每段路线两层。** 先由宽而柔的光带照亮地面，再由清晰实线确认方向。单层线条无论什么颜色，都会读成图表。

## 布局受什么约束

绘图活在固定的 1000×600 坐标空间里，被拉伸到页面给它的任何盒子中；而标签是真实 DOM，字号固定。所以屏幕变矮时，地标之间的像素间距会缩，卡片却不会。两个容易忘记的后果：

- 坐标是按地图允许的**最矮**盒子、以及**最高**的语言来排的——那是日文或英文，不是中文。
- 地图向标题背后延伸，但只有雾和等高线可以过去。带标签的地标压在文案上，等于把可读的东西盖在可读的东西上。

地图高度同时受视口高度约束，这样在笔记本屏幕上，下方 Demo 区块的顶边仍然露出来。那条边是页面还有内容的唯一提示。

## Demo：会生长的想法地图

Demo 是一段固定体验，背后没有 Agent。需要在后续改动中保住的，是这张地图的行为，而不是
里面的句子。

**整张地图留在窗口里。** 每个 storyboard 状态有自己的排布，随着想法长大，Agent 会重新
整理白板：节点上移、靠拢，而不是把画布继续拉长。节点高度在运行时测量——同一个节点，中文
是一行，日文可能是两行——任何会压到上方节点的节点都会被推开。如果完整的地图仍然比面板高，
就整体轻微缩小，而不是裁掉，也不是变成一条需要访客自己发现的长滚动。手机上地图是独立面板，
所以保持接近原始尺寸并允许滚动，同时把这一轮新增的内容滚到可视区域。

**所有语义节点都能被选中，但 `↗` 只表示可以进入分枝。** 点节点只会高亮它和相邻关系，并在
画布底部给出“继续聊、改一下”等轻量操作，不会立刻制造一段新对话。只有带 `↗` 的节点才多出
“深入讨论”，由用户显式进入分枝。分枝的结果可以合入当前结论、作为候选留在地图，或完全不保留。

## 字号阶梯

整页只用五级字号，在 `web/src/styles.css` 中声明为 `--fs-tag` 到 `--fs-lead`，不再
另外发明第六级。

| Token | 字号 | 用途 |
| --- | --- | --- |
| `--fs-lead` | 17px | 首屏引导文、原则条目标题，以及 Demo 里 Agent 说的话 |
| `--fs-body` | 16px | 默认正文：所有段落、列表和想法输入框 |
| `--fs-small` | 14px | 图注、附注、左侧路标、回答选项，以及想法地图上的所有文字 |
| `--fs-label` | 13px | 全大写等宽的区块标签、眉题和术语 |
| `--fs-tag` | 12px | 全大写等宽的元数据标签与状态药丸 |

**正文 16px，下限 14px。** Material 3 把 body-large 定为 16sp、body-medium 定为
14sp，可读文本到此为止；GOV.UK 的字号阶梯最小值是 16px，并且已经明确不再在小屏上
缩小；Apple iOS 的 Body 是 17pt。可交互的标签遵循同一条规则，所以按钮和导航从原来
的 10px 等宽提高到 14–15px。

**12–13px 只允许用于全大写等宽的元数据。** 全大写序列里每个字形都是大写高度，因此
12px 的标签大致相当于 16px 小写文本的大写高度，却不承担阅读负担——它们是一到四个词
的状态标记，不是句子。页面上小于 12px 的只剩几个 `aria-hidden` 的装饰符号。

**字号变大之后行高相应收紧。** 正文行高 1.7，小字 1.6–1.75，既高于 WCAG 2.2 文本间距
对段落要求的 1.5，又避免了 11px 文字才需要的 1.85。

有两处版式原本是按旧字号调过的，这次一起改：首屏两个操作改为上下堆叠而不是并排；
想法地图从 1120px 起就占满页面宽度，而不是 980px。

## 可访问性基线

- 普通文本颜色组合按 WCAG 2.2 的 4.5:1 最低对比度检查；大文本不能成为降低普通正文对比度的借口。
- 状态不只用颜色表示，也使用文字、编号、勾选或边界符号。
- 键盘焦点使用可见的外轮廓，页面保留跳过导航链接。
- 动效遵从系统的减少动态效果偏好。

设计依据：[W3C 对比度最低要求](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[W3C Animation from Interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)、[W3C `prefers-reduced-motion` 技术 C39](https://www.w3.org/WAI/WCAG22/Techniques/css/C39.html)、[W3C 文本间距](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing.html)、[Material 3 字号阶梯](https://m3.material.io/styles/typography/type-scale-tokens)、[GOV.UK 字号阶梯](https://design-system.service.gov.uk/styles/type-scale/)、[Apple HIG 字体规范](https://developer.apple.com/design/human-interface-guidelines/typography)。
