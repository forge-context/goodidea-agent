# GoodIdea LP 视觉系统与设计理由

[English](lp-visual-system.md) | [日本語](lp-visual-system.ja.md) | [中文](lp-visual-system.zh.md)

这份记录说明 LP 当前的视觉决定以及每个决定背后的原因。目标不是证明某种颜色天然代表某种心理，而是建立一套与产品行为一致、可以复用和验证的界面语言。

## 核心概念

GoodIdea 的产品过程是“发散想法 → 查证现实 → 收敛边界 → 产生行动”。因此，界面要同时具备两种气质：让人愿意开始探索，也让人相信系统会在关键处停下来。

## 设计决定

| 决定 | 实装 | 原因 |
| --- | --- | --- |
| 品牌气质 | 从 Forge 风格的冷蓝工程界面改为温暖的紫、珊瑚和青绿 | GoodIdea 不是审计工具。它先接住还不完整的想法，再逐步收敛；更有温度的色彩能把“可以开始”与“有边界”同时表达出来。 |
| 主色 | 暖葡萄紫 `#7A3F9F` | 原来的蓝紫在冷白背景和大面积按钮中容易被看成蓝色。暖葡萄紫仍表示“探索/当前行动”，但更贴近创意产品，而不是通用 SaaS 或工程工具。白字对比度约为 6.91:1。 |
| 辅助色 | 青绿 `#087B66` 表示证据成立或完成；珊瑚 `#BC4637` 表示边界或需要注意 | 把正向证据与风险边界分开，避免所有状态都挤在同一种品牌色中。颜色同时配有文字、符号或标题，不依靠色觉单独传递信息。 |
| 背景与正文 | 暖白 `#FFFAF7` 配深紫黑 `#241936` | 暖白减少主色被视觉感知为蓝色的倾向，也降低工程工具的冷硬感。正文对比度约为 15.99:1，弱化正文约为 6.30:1。 |
| Hero 构图 | 左侧保留明确承诺，右侧改为生成式想法粒子场 | 左侧说明结果，右侧在用户阅读产品 Demo 前，先让“模糊想法 → 清晰方向”变成可感知的视觉体验。阶段路径留在 Demo 内，在那里才有功能含义。 |
| 标题表现 | 主标题第二行使用紫到珊瑚的有限渐变 | 渐变把探索到行动的转变压缩为一个视觉线索，只用于大标题，不用于正文和按钮，避免牺牲可读性或形成视觉噪声。 |
| 品牌标记 | 用“未闭合的 G 路径 + 珊瑚色亮点”替代圆角方块里的字母 G | 未闭合路径代表想法仍有探索空间，亮点代表它收敛为明确下一步的瞬间。页头、Demo 和页脚复用同一个专属矢量标记。 |
| 操作图标 | 向下浏览和打开实现统一使用 16px 圆角线条 SVG | 字体箭头在不同系统中粗细和形状不一致。统一线宽能让首屏两个操作看起来属于同一套设计语言。 |
| 卡片形状 | 使用 12–26px 的分层圆角，不使用完全方正面板 | 圆角降低“审计控制台”的距离感；不同层级使用不同半径，帮助区分按钮、内容卡和大型产品 Demo，而不是随意装饰。 |
| Demo 地位 | 保持 Demo 为页面最大的实体，并用阶段颜色改变顶部状态线 | 面试或访问者应先看到产品行为，而不是先读功能清单。状态线在不重排页面的前提下反馈“研究、提案、交接”的变化。 |
| Agent 回答结构 | 可行性阶段保持为一条连续 Chat：第一句给结论，证据嵌入正文，两个紧凑选项放在同一条消息末尾 | 把回答、说明、下一步和问题拆成多张卡片会分散注意力。同一条对话让用户先判断是否可做，再在原位置直接回答。 |
| 证据交互 | 证据附着在回答中的关键主张上；悬停或键盘聚焦显示来源，点击打开原文 | 用户不需要展开证据抽屉再逐条匹配结论。出处与主张保持在同一阅读位置，同时保留继续求证的入口。 |
| 信息密度 | 市场现实、关键问题、MVP 边界分成连续卡片，每次只出现当前需要的动作 | 采用渐进披露，降低用户一次要处理的信息量，也和 Agent“一次只问一个高价值问题”的产品原则一致。 |
| CTA 层级 | 每屏只有一个实心主操作，次操作使用白底或文本形式 | 明确下一步，防止“试 Demo”“看 GitHub”“修改提案”等动作在视觉上相互竞争。 |
| 动效 | 标题使用遮罩揭幕；粒子响应鼠标，并从散乱状态汇聚成未闭合的 G 标记 | 首屏要像创意体验，而不是工作流操作教学。品牌化变形承担产品隐喻；进入 Demo 后，动效仍保持克制并服务状态反馈。 |
| 减少动态效果 | `prefers-reduced-motion: reduce` 下关闭动画、平滑滚动和过渡 | 系统偏好减少动态效果的用户应得到同样完整的信息。静态界面不依赖动画才能理解。 |
| 响应式 | 桌面双栏；平板把阶段栏横向展开；手机改为单栏并隐藏次要导航 | 保留各尺寸下的阅读顺序和核心操作，不只是把桌面版等比例缩小。 |
| 字体 | 三种语言使用各自的系统字体栈，大标题统一采用真实存在的 600 字重，等宽字体只保留给真正的技术元数据 | 页面不再依赖实际没有加载的 Inter。中文标签使用中文字体度量，移除只适合拉丁文的大写和字距规则，并设置语义换行点，避免把“开始”这类词从中间拆开。 |
| 图像策略 | 当前不增加无关照片或抽象插画 | 现阶段最有说服力的视觉是可交互产品行为。等品牌资产和真实案例成熟后，再评估是否需要原创视觉，而不是用库存图分散焦点。 |

## 可访问性基线

- 普通文本颜色组合按 WCAG 2.2 的 4.5:1 最低对比度检查；大文本不能成为降低普通正文对比度的借口。
- 状态不只用颜色表示，也使用文字、编号、勾选或边界符号。
- 键盘焦点使用可见的外轮廓，页面保留跳过导航链接。
- 动效遵从系统的减少动态效果偏好。

设计依据：[W3C 对比度最低要求](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[W3C Animation from Interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html)、[W3C `prefers-reduced-motion` 技术 C39](https://www.w3.org/WAI/WCAG22/Techniques/css/C39.html)。
