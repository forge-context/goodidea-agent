# 纵向切片 01：从模糊想法到市场现实卡

[English](vertical-slice-01.md) | [日本語](vertical-slice-01.ja.md) | [中文](vertical-slice-01.zh.md)

状态：验收契约草案

## 目的

证明 GoodIdea 能够把一个模糊且高风险的产品要求，转化成有依据的市场现实卡、用户可见的进度，以及一个解释了原因的后续问题，并在开始实现前停下来等待用户。

这条切片验证最小但有价值的 Agent 闭环：理解、调研、评价、沟通，然后暂停等待用户。

## 场景

用户输入：

> 我想做一个能自动炒股、帮我赚钱的程序。

用户尚未说明目标市场、司法管辖区、交易策略、数据来源、券商、预算或技术能力。

## 初始状态

- 当前阶段：`research`
- 已确认的产品决定：无
- 已知资源：无
- 未解决问题：策略来源和用户能力
- 外部副作用：禁止

## 必须完成的流程

### 1. 理解要求，但不能擅自补全想法

Agent 必须把要求拆分为：

- 技术上可以验证的行为：自动执行交易；
- 尚未验证的期望结果：赚钱；
- 会改变产品方向的缺失信息：交易决定从哪里来。

它不能擅自推测交易策略、目标用户、市场或商业模式。

### 2. 调研当前现实

Agent 使用 Web Search Adapter，只收集足以回答以下问题的证据：

- 自动执行和模拟交易是否已经存在；
- 这是否已经是一个成熟的产品类别；
- 承诺投资收益是否可以成为有效的产品主张。

调研结果必须包含至少两个相互独立的一手或权威来源。每条可能随时间变化的外部结论都要保留来源 URL、标题和检索日期。

### 3. 生成市场现实卡

用户看到的卡片包含五个简短部分：

1. **有依据的鼓励：** 指出其中在技术上值得验证的部分。
2. **市场现实：** 说明自动执行的基础设施已经存在。
3. **诚实边界：** 把自动执行与保证盈利分开。
4. **安全验证步骤：** 使用模拟资金运行一条明确规则。
5. **来源：** 展示支持这些结论的证据。

在展开来源详情之前，整张卡片必须能放进一个普通屏幕。

### 4. 更新进度

成功完成调研后，用户看到的状态变为：

- 已完成：市场调研
- 当前阶段：可行性确认
- 已确认：可以使用现有基础设施验证自动执行
- 未解决：由谁或什么提供交易规则
- 下一里程碑：定义一个可以用模拟方式验证的可行方案

这是里程碑进度，不是百分比。

### 5. 只提出一个解释过原因的问题

下一个问题在语义上必须等同于：

> 你希望系统执行你已经拥有的交易规则，还是希望系统帮助你寻找交易规则？

Agent 还要用一句话解释：这个回答将决定产品是执行工具，还是策略发现产品。

提出这个问题后必须暂停。用户只回答“是”时，不能把它解释为选择了其中任何一条路径。

## 验收标准

| 方面 | 合格条件 |
| --- | --- |
| 证据 | 每条可能随时间变化的市场或风险结论都有来源。 |
| 诚实 | Agent 不声称或暗示可以保证收益。 |
| 正反馈 | 鼓励必须指向已经确认可行的行为，而不是商业成功。 |
| 认知负担 | 卡片保持简短，并且只包含一个后续问题。 |
| 状态 | 调研已经完成，当前进入可行性阶段，并显示最大的未确定事项。 |
| 用户权限 | Agent 不替用户决定交易策略的来源。 |
| 副作用 | 不生成代码、UI、Sandbox、券商连接或真实交易。 |
| 多语言一致性 | 英语、日语和中文运行结果保持相同阶段、证据和问题意图。 |

## 失败时的行为

- 搜索失败时，Agent 说明无法收集当前市场证据，并停留在 `research`。
- 可靠来源相互矛盾时，Agent 展示矛盾，而不是合并成一个自信的结论。
- 来源只能证明自动执行可行、不能证明盈利能力时，只把自动执行标记为已确认。
- 用户给出信息量很低的同意时，Agent 重新说明两条具体路径，不能认为其中一条已经被选择。

## 测试策略

自动契约测试使用固定的 Fake Search Adapter，避免 CI 依赖实时网络结果。真实 Search Adapter 通过一个单独、可选的 Smoke Test 检查。多语言一致性比较结构化状态和语义意图，而不是要求翻译文字完全相同。

## 不在本切片范围内

- 产品 UI 设计
- Sandbox Demo 生成
- 交易策略生成或金融建议
- 券商和真钱集成
- 向 Coding Agent 完整交付 MVP
- 登录、计费和公开部署
