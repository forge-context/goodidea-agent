# Vertical Slice 01: 曖昧なアイデアから市場の現実カードへ

[English](vertical-slice-01.md) | [日本語](vertical-slice-01.ja.md) | [中文](vertical-slice-01.zh.md)

状態: Draft acceptance contract

## 目的

GoodIdea が、高リスクで曖昧な要求を、根拠のある市場の現実カード、利用者に見える進捗、理由を説明した一つの質問へ変換し、実装を始めずに停止できることを証明します。

この切片では、解釈、調査、評価、伝達、利用者入力待ちという最小限の Agent loop を検証します。

## シナリオ

利用者入力:

> 自動で株を売買し、利益を出してくれるプログラムを作りたい。

利用者は対象市場、法域、取引戦略、データ源、Broker、予算、技術力をまだ示していません。

## 開始時点の状態

- 現在の段階: `research`
- 確認済みのプロダクト判断: なし
- 既知のリソース: なし
- 未解決の問い: 戦略の出どころと利用者の能力
- 外部への副作用: 禁止

## 必須フロー

### 1. アイデアを黙って補完せずに解釈する

Agent は要求を次の三つに分けます。

- 技術的に検証可能な挙動: 取引の自動執行
- 未検証の期待結果: 利益を出すこと
- プロダクトを変える不足情報: 売買判断をどこから得るか

戦略、対象利用者、市場、ビジネスモデルを推測してはなりません。

### 2. 現在の現実を調査する

Agent は Web Search adapter を使い、次の三点だけに答えるための十分な根拠を集めます。

- 自動執行とペーパートレードが既に存在するか
- 既に成立したプロダクトカテゴリか
- 投資収益の約束が妥当なプロダクト表現か

調査結果には、独立した一次情報または権威ある情報源を二つ以上含めます。外部変化の影響を受ける各主張は、URL、タイトル、取得日を保持します。

### 3. 市場の現実カードを作る

利用者に見せるカードは、短い五つの部分で構成します。

1. **根拠のある後押し:** 技術的に検証する価値がある部分を示す。
2. **市場の現実:** 執行基盤が既に存在することを説明する。
3. **誠実な境界:** 自動執行と利益保証を分ける。
4. **安全な検証手順:** 一つのルールを仮想資金で動かす。
5. **出典:** 主張に利用した根拠を示す。

出典の詳細を展開する前のカードは、通常の一画面に収まらなければなりません。

### 4. 進捗を更新する

調査が成功したあとの表示状態は次のとおりです。

- 完了: 市場調査
- 現在の段階: 実現可能性の確認
- 確認済み: 既存基盤を使って自動執行を検証できる
- 未解決: 誰が、または何が取引ルールを提供するか
- 次の節目: Simulation 可能な実現方法を一つ定義する

これは割合ではなく、節目による進捗です。

### 5. 理由付きの質問を一つだけ行う

次の質問は、意味として以下と同じものにします。

> 既に持っている取引ルールをシステムに実行させたいですか。それとも、取引ルール自体をシステムに探させたいですか。

この回答によって、執行ツールなのか戦略発見プロダクトなのかが変わることも一文で説明します。

この質問のあとで実行を停止します。「はい」のような情報量の少ない回答で、どちらかを選んだことにはしません。

## 受け入れ基準

| 観点 | 合格条件 |
| --- | --- |
| 根拠 | 時間とともに変わり得る市場またはリスクの主張に出典がある。 |
| 誠実さ | 収益保証を主張または示唆しない。 |
| Positive feedback | 商業的成功ではなく、確認済みの実現可能な挙動を評価する。 |
| 認知負荷 | カードは簡潔で、後続の質問は一つだけである。 |
| 状態 | 調査が完了し、実現可能性が現在段階となり、最大の不確実性が見える。 |
| 利用者の権限 | 戦略の出どころを Agent が利用者の代わりに決めない。 |
| 副作用 | Code、UI、Sandbox、Broker 接続、実取引を作らない。 |
| 言語の同等性 | 英語、日本語、中国語で段階、根拠、質問の意図が同じである。 |

## 失敗時の挙動

- Search に失敗した場合、現在の市場根拠を収集できなかったと伝え、`research` に留まる。
- 信頼できる情報源が食い違う場合、一つの確信した結論へ混ぜず、食い違いを表示する。
- 執行可能性だけが確認でき、収益性を確認できない場合、執行可能性だけを確認済みにする。
- 利用者が情報量の少ない同意を返した場合、どちらも選択済みにせず、二つの具体的な経路をもう一度示す。

## テスト方針

自動契約テストは固定の Fake Search adapter を使い、CI を Live network に依存させません。実際の Search adapter は、別の opt-in smoke test で確認します。言語の同等性は翻訳文の完全一致ではなく、構造化された状態と意味上の意図で比較します。

## 対象外

- プロダクト UI 設計
- Sandbox Demo の生成
- 取引戦略の生成または金融助言
- Broker と実資金の統合
- Coding Agent への完全な MVP 引き渡し
- 認証、課金、公開デプロイ
