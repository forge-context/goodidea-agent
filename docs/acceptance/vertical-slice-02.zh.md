# 纵向切片 02：从用户决定到 Coding Agent 交接

[English](vertical-slice-02.md) | [日本語](vertical-slice-02.ja.md) | [中文](vertical-slice-02.zh.md)

状态：离线契约已实现

## 目的

证明 GoodIdea 可以从第一个用户决定恢复，制定带约束的可行性路径，提出 MVP 边界，并且只在用户批准眼前这份提案后生成 Coding Agent 交接包。

## 必须实现的流程

1. 模糊同意不能选择产品路径。
2. 只有明确的策略来源回答才会保存为 `decided_by=user`。
3. 根据用户选择生成可行性产物和 MVP 提案。
4. 提案分别列出要做、不做、前提、用户流程和验收条件。
5. 请求修改时保持未批准状态，不产生交接包。
6. 用户批准必须绑定到提案 ID。
7. 只有这时才能产生 Coding Agent 交接包，并把阶段改为 `handoff`。

## 安全边界

两条自动交易路径都禁止真钱订单和收益保证。执行路径只使用用户提供的一条规则和模拟订单；探索路径只比较固定且透明的候选规则，不提供策略推荐。

## 验收条件

- 证据、产品决定、未解决问题和批准记录保持分离。
- SQLite 可以恢复完整结果，并分别查询当前决定和批准记录。
- API 拒绝跳过顺序的状态迁移。
- 交接包保留验收条件、证据 ID、约束和用户批准。
- 外部副作用始终关闭。
- 英语、日语和中文产生语义一致的阶段和边界。
